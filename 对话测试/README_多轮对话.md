# 2.2.3 带工具调用的多轮交互：Agent 的核心循环

这个示例在 2.2.2 单次 API 调用的基础上，增加了 Agent 最关键的执行循环：

```text
用户消息 → 模型判断 → 请求工具 → 本地执行工具
                    ↑              ↓
                    └── 工具结果 ──┘
                           ↓
                       最终回答
```

只要模型继续请求工具，程序就继续执行并把结果发回模型；当模型不再请求工具、返回普通文本时，本轮结束。所有消息会留在 `messages` 中，因此下一次用户输入可以引用前文。

## 示例工具

- `calculate(expression)`：安全计算数学表达式，不使用 `eval`
- `get_current_time()`：获取运行程序的计算机当前本地时间

工具采用白名单调用，模型只能选择程序明确注册的函数。

## 交互式多轮对话

在项目根目录运行：

```powershell
conda activate agent
python ".\对话测试\tool_call_agent.py"
```

可以依次输入：

```text
用户：请计算 23 * 47
用户：把刚才的结果再加 100
用户：现在几点？
用户：exit
```

第二个问题能够引用第一个问题，是因为程序一直保留同一个 `messages` 列表。

## 单回合测试

无需进入交互模式也可以直接传入问题：

```powershell
conda run -n agent python ".\对话测试\tool_call_agent.py" `
  --prompt "请使用计算器计算 (23 + 7) * 4"
```

运行过程中会显示工具调用和结果：

```text
[工具调用] calculate({"expression": "(23 + 7) * 4"})
[工具结果] {"ok": true, "data": {"expression": "(23 + 7) * 4", "result": 120}}
助手：计算结果是 120。
```

完整上下文默认保存到 `agent_history.json`，它是一个经过缩进格式化的标准 JSON 文件，每次保存当前这次程序运行的完整对话。

## 核心逻辑

核心循环位于 `run_agent_turn()`：

1. 把当前 `messages` 和工具定义发送给模型。
2. 将模型回复加入 `messages`。
3. 如果存在 `tool_calls`，解析参数并执行对应的本地函数。
4. 以 `role: tool` 将工具结果加入 `messages`。
5. 回到第 1 步，让模型根据工具结果继续判断。
6. 模型返回普通文本时结束当前用户回合。

程序默认最多允许单个用户回合执行 5 轮工具调用，避免模型陷入无限循环。可以通过 `--max-tool-rounds` 调整。

## 关于 0.6B 模型

`qwen3:0.6b` 已支持工具调用，但参数量较小，偶尔可能直接计算、跳过工具，或者生成不够准确的工具参数。这属于模型决策能力的限制；Agent 循环仍会正确处理模型实际返回的 `tool_calls`。需要更稳定的复杂工具规划时，可以换用更大的、支持 tools 的模型，并通过 `--model` 指定模型名。


## 额外知识点
1. role为assistant或者tool的消息，是需要代码提取必要消息再添加到messages列表中（需要预处理）。
2. 工具的调用是需要本地代码解析assistant消息中的tool_calls中的json字符串，然后调用实际处理函数。
